# Task: map

Draft an architecture map of the project from its main branch, so the
architect reviewer judges every review against the same picture instead of
re-learning the layout each run.

The map is a generated draft, saved locally and never committed. A project
that keeps a reviewed `ARCHITECTURE.md` does not need it; reviews prefer that
file when it exists.

**Done when:** `.modus/architecture.md` is written, and the person has the
one-line message from step 6.

## Steps

1. **Pick the commit.** The ref the person gave, else `origin/main`, else
   `main`. Record its SHA. The map describes that commit only: a feature
   branch or uncommitted work must not leak into it.

2. **Read that commit, not the working tree.** If the working tree is on that
   commit with no changes (`git status --porcelain` prints nothing), read
   files directly. Otherwise list them with `git ls-tree -r --name-only <SHA>`
   and read them with `git show <SHA>:<path>`.

3. **Explore what the architect checks** (`roles/architect.md`), and nothing
   else:
   - **layout** — where each kind of code lives;
   - **entry points** — how requests, commands and events get in; the
     project's packs list them for its stack;
   - **the codebase's ways** — how it reads settings, reaches the database,
     makes HTTP calls, handles errors, logs, caches, runs background work;
   - **dependencies** — which way they point, and what must not depend on
     what;
   - **public surface** — routes, hooks, events, options and public APIs that
     other code or other plugins rely on.

   Cite a path for each claim. When the code does a thing two ways, say so;
   that is a finding the architect will want. When you cannot tell, put it
   under **Unsure** rather than guessing.

4. **Keep it local.** Create `.modus/.gitignore` containing `*` if it is
   missing. If git tracks anything under `.modus/`, stop and tell the person
   rather than writing into a committed folder.

5. **Write `.modus/architecture.md`** in the format below. Keep it under about
   200 lines. It is read on every review, so a file listing or a tour of the
   code costs more than it helps.

6. **Tell the person it is done**, in one line: `Map saved:
   .modus/architecture.md (main @ <short SHA>)`. Everything else, including
   what is unsure, is in the file.

## Format

```markdown
# Architecture map

generated by modus from main @ <short SHA> on <date> — a draft, not reviewed

## What this is
<one paragraph: what the project does, and its stack>

## Layout
- `<path>/` — <what lives here>

## Entry points
- <kind> — <where, and how it is registered>

## How things are done here
- settings — <the way, with a path>
- data access — …
- HTTP calls — …
- errors and logging — …
- caching — …
- background work — …

## Dependencies
<which way they point; what must not depend on what>

## Public surface
<what other code relies on and would break if it changed>

## Unsure
<what the map could not establish>
```

## Staleness

The map records the commit it describes. The architect reviewer compares it
with the review's base: when main has moved far beyond it, or the code under
review contradicts it, the review says the map may be stale. Re-run the task
to refresh it; it overwrites the old map.
